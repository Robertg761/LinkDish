# Restricted iPhone extraction endpoint

`POST /extract/ios` selects the server-side `ios_public_domain_v1` policy. The existing `/extract` endpoint remains available for Android/web and older clients. This is a policy for requests sent by the new iPhone build, not device attestation or a claim that a modified client cannot call other public endpoints.

The fixed route selects the policy regardless of a client platform header. Vercel rewrites it to the existing extract function with `path=ios`, avoiding a new serverless function. Fastify exposes the same route. Existing rate limiting and billing apply; unsupported initial URLs are rejected before billing authorization or source access.

The restricted runtime uses the shared recipe-source list, public-IP validation and the DNS-rebinding-safe transport. It validates every HTTP redirect and linked recipe-page fetch. It does not inherit the general runtime's browser/social/video/creator-search fetchers or extraction cache. It uses an identifying bot user agent and does not retry challenges as a different browser. Robots must return HTTP 200, include the wildcard agent, and have no nonempty Disallow directive; any change fails closed pending review. The conservative robots check runs once per extraction, including retries. Gemini fallback processes fetched text; its request does not enable URL-context or browsing tools.

Remote website artwork is omitted from URL results because the general image proxy does not yet enforce the source policy. User-supplied photos/text continue through the existing pipeline and AI consent. Final source URLs are checked again before billing commits a successful import. The shared policy also drives the new iPhone client's entry validation; the client must use `/extract/ios` without falling back to `/extract` on an error.

Validation includes cross-host/query/protocol redirect rejection before the next network call, permitted redirects, secondary URLs, robots changes/redirects, bot challenges, SSRF rejection, cache/fetcher isolation, Vercel and Fastify route enforcement with spoofed platform headers, and API-client 404 fail-closed behavior. Full repository validation passes. A live local request fetched the allowed recipe with no browser; without Gemini configured locally, the confidence gate requires fallback and returns `parse_failed`. Production verification must test the endpoint with its deployed Gemini configuration before relying on that import flow.

Deploy backend changes independently of the unmerged mobile PR. Verify the source-policy response header and the allowed/blocked import paths on production before releasing build 39. Content Rights remains an owner declaration; this endpoint does not resolve rights to built-in, saved, uploaded or shared recipes, and does not automatically make older binaries compliant with the new restriction.
